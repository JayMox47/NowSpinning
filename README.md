# Now Spinning — Spotify album display

A fullscreen, single-page album-poster display for a digital frame or kiosk. It shows the active Spotify album, falls back to a rotating standby list, and includes a discreet manual album picker.

## Features

- Spotify Authorization Code flow with PKCE; no client secret or backend required
- Five-second currently-playing polling and 30-second standby carousel
- Manual search and pin mode
- Automatic access-token refresh with device-local token storage
- Dominant cover-color ambient background
- Fullscreen control and three-second cursor/control auto-hide
- Responsive portrait, landscape, touch, and keyboard-friendly layout

## Project structure

```text
app/
  MusicPoster.tsx  # kiosk UI and display-mode controller (app.js equivalent)
  config.ts        # typed access to public configuration
  spotify.ts       # PKCE, tokens, refresh, and Spotify API calls
  globals.css      # complete responsive poster styling (style.css equivalent)
  layout.tsx       # document shell (index.html equivalent)
  page.tsx         # single route entry
public/
  config.js        # Spotify Client ID, redirect URI, and standby album IDs
```

This project uses the Vite-powered Sites/Vinext starter, so `layout.tsx` provides the HTML document shell instead of a handwritten `index.html`. The requested concerns remain separated into the same small modules.

## 1. Register a Spotify application

1. Sign in at the [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Choose **Create app**.
3. Give the app a name and description, accept Spotify's terms, and create it.
4. Open **Settings** and copy the **Client ID**. A client secret is not used and must never be added to this project.
5. Under **Redirect URIs**, add the exact URL where the display will run. For local development use `http://127.0.0.1:3000/` or the exact local URL printed by your development server. Add your final HTTPS production URL separately.
6. Save the app settings.

Spotify may require you to add permitted users while an app remains in development mode. Add the Spotify account used by the frame from the dashboard's user-management area if sign-in is denied.

## 2. Configure the frame

Edit `public/config.js`:

```js
window.MUSIC_FRAME_CONFIG = {
  spotifyClientId: "your_client_id_here",
  redirectUri: window.location.origin + window.location.pathname,
  standbyAlbumIds: ["spotify_album_id_1", "spotify_album_id_2"],
  pollIntervalMs: 5000,
  carouselIntervalMs: 30000,
};
```

An album ID is the final part of a Spotify album URL: `https://open.spotify.com/album/ALBUM_ID`.

The redirect URI generated by `config.js` must exactly match one registered in Spotify, including protocol, host, port, path, and trailing slash. Spotify allows PKCE apps to expose the Client ID, but never put a Client Secret in browser code.

## 3. Run locally

```bash
npm install
npm run dev
```

Open the local URL, choose **Connect Spotify**, and approve access. Use **Select album** for search/pin mode and the expand icon for fullscreen.

## 4. Build and host

```bash
npm run build
```

Deploy the generated project to any compatible static/edge host. After deployment, add the production URL to Spotify's Redirect URIs and make sure `public/config.js` resolves to that same URL. HTTPS is required by Spotify for non-loopback production redirect URIs.

## Kiosk notes

- Sign into Spotify once on the frame; tokens are stored only in that browser's `localStorage`.
- Browser privacy cleanup, site-data clearing, or changing the origin will require reconnecting.
- If Spotify is paused, unreachable, or signed out, the display continues in standby mode.
- Browsers generally require a user gesture to enter fullscreen, so use the fullscreen button once after startup.
- For unattended launch, use the browser's own kiosk/fullscreen startup flags and disable sleep at the operating-system level.
